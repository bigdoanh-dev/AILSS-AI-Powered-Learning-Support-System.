# AILSS P12.4 — Lecturer Contract Matrix

Baseline: corrected public OpenAPI and API registry after the P12.4 preflight correction. This matrix limits the Web Lecturer experience to existing Gateway routes and runtime authorization.

| Lecturer capability                  | Machine API IDs        | Web route                                                                       | Runtime rule / UI consequence                                                                                                                                                                                  |
| ------------------------------------ | ---------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Guard                                | IDN-05 (`GET /me`)     | `/app/teaching/*`                                                               | Requires `status=ACTIVE`, `role=LECTURER`, and `lecturerVerified=true`. An active but unverified Lecturer sees a verification-required page and no teaching mutation UI. Other roles are rejected.             |
| Course overview and create           | LRN-01, LRN-03, LRN-05 | `/app/teaching`, `/app/teaching/courses/new`, `/app/teaching/courses/:courseId` | There is no owned-courses endpoint. The overview uses the public catalog and labels it accordingly; ownership is established by detail/mutation responses. Creation requires an idempotency key.               |
| Course edit and review submission    | LRN-06, LRN-07         | `/app/teaching/courses/:courseId`                                               | Owner Lecturer only. Edit is DRAFT-only in runtime. Submit-review is an explicit command and never presented as publication.                                                                                   |
| Lesson list, detail, create, edit    | LRN-10–13              | `/app/teaching/courses/:courseId/lessons`, `/app/teaching/lessons/:lessonId`    | Owner Lecturer mutations require idempotency. Lesson content accepts an existing object reference; this phase does not invent a Learning upload API.                                                           |
| Course roster                        | LRN-16                 | `/app/teaching/courses/:courseId/roster`                                        | Owner Lecturer only, read-only roster projection.                                                                                                                                                              |
| Offering list, create, edit, publish | LRN-24–28              | `/app/teaching/offerings`, `/app/teaching/offerings/:offeringId`                | Owned list is authoritative. Create requires a course id; LIVE_COHORT also requires a class id. Patch is DRAFT-only. Publish is explicit.                                                                      |
| Class list, create, detail, edit     | CLS-01–03, CLS-06      | `/app/teaching/classes`, `/app/teaching/classes/:classId`                       | Owned list is authoritative. | Class roster and join-code reset     | CLS-07–08              | `/app/teaching/classes/:classId/roster`                                         | Owner Lecturer read/reset. The returned join code is transient UI data and is not persisted by Web.                                                                                                            |
| Announcements                        | CLS-09–10              | `/app/teaching/classes/:classId/announcements`                                  | Owner creates; class member/owner reads by month. Create requires idempotency.                                                                                                                                 |
| Sessions and schedule publication    | CLS-11–14, CLS-20      | `/app/teaching/classes/:classId/schedule`, `/app/teaching/sessions/:sessionId`  | Session create may materialize bounded weekly recurrence. | Attendance                           | CLS-16, CLS-19         | `/app/teaching/sessions/:sessionId/attendance`                                  | Authorized class Lecturer reads the roster. Manual attendance applies only to OFFLINE sessions and uses optimistic `attendanceVersion` plus idempotency. Online presence evidence cannot be overwritten.       |
| Quiz authoring and target list       | ASM-01–05              | `/app/teaching/assessments`, `/app/teaching/assessments/:quizId`                | Lecturer creates; owner edits/publishes. Target membership/ownership is checked by Assessment runtime. Correct answers are available only to eligible owners.                                                  |
| Quiz results                         | ASM-10                 | `/app/teaching/assessments/:quizId/results`                                     | Owner Lecturer reads month-bucketed, cursor-paginated results. Admin behavior remains deferred by runtime.                                                                                                     |
| AI document upload                   | AI-07–09               | `/app/teaching/ai`                                                              | Intent validates name, MIME, byte count, and SHA-256. Browser uploads directly to the returned presigned URL, then completes using the exact intent fields. Web never stores document bytes or presigned URLs. |
| AI generation, jobs, drafts, cancel  | AI-01–04, AI-06        | `/app/teaching/ai`, `/app/teaching/ai/jobs/:jobId`                              | Verified Lecturer and owner-only job projections. Job list requires state and month. Generate/cancel require idempotency.                                                                                      |
| AI human approval                    | AI-05                  | `/app/teaching/ai/jobs/:jobId`                                                  | Approval sends the complete reviewed Objective Quiz v2. No auto-approval is exposed. Successful approval creates an Assessment DRAFT, never a published quiz.                                                  |
| AI usage                             | AI-10                  | `/app/teaching/ai`                                                              | Read-only Lecturer quota/usage projection.                                                                                                                                                                     |

The Lecturer adapter is a separate allowlist under `/web-session/lecturer/*`. It validates path, query, JSON body, command headers, canonical `/me`, and the verified Lecturer predicate before forwarding. Responses are returned through a fail-closed Lecturer envelope that rejects credentials, service tokens, presigned upload fields outside AI intent, and other privileged internals. Public catalog reads remain available through the same authenticated adapter only where this matrix names them.

Unsupported or deferred in this phase: an owned-course index, Learning lesson-file upload, deletion flows, class-member removal, grading overrides, CSV export, admin quiz-result access, and automatic AI approval. The UI states these limits where they affect a task rather than synthesizing APIs or data.

All adapter errors preserve the registered upstream code while mapping common `401`, `403`, `404`, validation, state, cursor and version conflicts to bounded Vietnamese UI copy. No operation in this matrix requires current-password reauthentication; Admin-only course publication/archive and INT-11 moderation remain outside the Lecturer adapter.
