## Route decisions and runtime details

- `/app`: bounded own courses/classes and current UTC-month notifications; no global analytics.
- `/app/learn`: LRN-15 own courses and LRN-02 prefix search (3–20 normalized characters, limit12, opaque cursor). LRN-01 requires known category ID so not used as unfiltered catalog.
- `/app/learn/:courseId`, `/app/learn/:courseId/lessons/:lessonId`: LRN-03/10/12/14/17/18; published detail implies publication, progress success authorizes review eligibility. Lesson `contentUrl` is a short-lived supported download/open link; no content-type or inline text contract. No per-lesson completion GET: display canonical aggregate and current command acknowledgement only.
- `/app/progress`: choose own course, then LRN-17; no fan-out over all courses.
- `/app/classes`, `/app/classes/:classId`: CLS-05/04/02/13/15/17/10. Class list returns class DTO, not member state; never invent it. Sessions and own schedule require from/to UTC dates <=31 days. Attendance month YYYY-MM; announcement month YYYY-MM-01. Meeting URL only via CLS-14 when server window permits. No Student attendance write.
- `/app/assessments`: choose enrolled course or class then ASM-05; `/app/assessments/:quizId` ASM-02 with explicit start-or-resume action ASM-06. `/app/attempts/:attemptId` ASM-07/08; `/app/attempts/:attemptId/result` ASM-09 (no invented resultId lookup). States CREATED/IN_PROGRESS/SUBMITTED/EXPIRED. Answer payload: answers array of questionId + exactly selectedOptionId/selectedOptionIds/value/text, clientSubmittedAt fixed for retry.
- Course/Class discussion uses INT-01..04; Course reviews INT-05..08. Cursor in `meta.page`, array in data. If-Match is quoted `"vN"`. One-level replies only; soft-deleted body is null.
- `/app/notifications`: NOT-01 data.items + data.page, YYYY-MM UTC month, max50; read sends `x-notification-locator` unchanged. DTO readAt null means unread. CLASS_ANNOUNCEMENT source.contextId links to guarded class detail.
- Adapter preserves meta pagination explicitly for Student reads; original auth adapter previously unwrapped only data, which would lose catalog/comment cursors.
- All protected reads can fail401/403/404/503; services also use400 invalid cursors,409 version/idempotency/attempt conflicts,422 invalid input,429 throttling. Never render raw technical errors. No client authorization replaces server checks.

## Verified runtime nuances

- ASM-07 returns attempt metadata only, **not questions**. Opening the attempt page reads state first; an explicit resume action calls ASM-06 to obtain the pinned question snapshot. Browser never persists questions or answer drafts in history/storage.
- LRN-14 resolves `defaultOfferingId(courseId)`. LRN-24 creates a random Offering ID, so a newly published Course without the legacy default Offering returns `404 OFFERING_NOT_AVAILABLE`. UI reports unavailable registration. Real acceptance creates/publishes an Offering through LRN-24/26, then obtains entitlement through LRN-19/21 simulated local commerce **outside the Web UI**. No canonical Student data is seeded. This is an existing backend provisioning limitation, not a new contract.
- LRN-10 is the published syllabus read and does not itself prove entitlement. Review-create visibility depends on successful LRN-17 (ACTIVE entitlement + published Course) and server percent >=20; the mutation rechecks eligibility.
- Explicit adapter body ceiling is 262144 bytes for each Student operation, including the bounded maximum 200-answer submit; upstream timeout15s / browser timeout20s. Query schemas reject duplicate and unknown keys; path shapes reject encoding, traversal and unsupported operations.
