## Internal authorization used here

| ID         | Caller → owner         | Contract                                                                                                                                                                                                                                                                                                           |
| ---------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| INT-IDN-02 | API Gateway → Identity | POST `/internal/v1/admin/step-up-authorizations`, 800 ms, fail closed. Gateway signs service identity and sends actor/action/resource/current password to Identity. Proof is audience-bound to Interaction moderation; application authority remains Identity. This is current-password reauthentication, not MFA. |

Comment eligibility is checked against Learning for COURSE and Classroom for CLASS using audience/purpose-bound actor context. Reviews use Learning entitlement and progress authority. Notifications use Q-NOT-001 actor+month ownership and Q-NOT-002 only for worker recovery identity; no public `userId` parameter exists.

## Web binding

- Student discussion pagination keys include session actor in the data hook and resource type/id in the path; changing resource remounts/rescopes and resets cursor state.
- Create/edit/delete/report commands retain one logical Idempotency-Key across ambiguous retry; successful or changed commands rotate it. Edit/delete also forward canonical `If-Match`.
- Student and Lecturer reply-on-reply resolves to its root; arbitrary nesting is not exposed.
- Admin moderation is a dedicated ADMIN route, with no MODERATOR role, guard, badge, login, or navigation.
- Notification locator is forwarded only in the header and never placed in a URL. Class announcement links are emitted only for UUID context IDs and land on a Student-guarded Class route.
- No likes, reactions, direct messages, social/global feed, popularity, sentiment, or fabricated unread count exists.
